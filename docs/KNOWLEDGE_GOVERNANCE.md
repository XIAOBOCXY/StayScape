# 文旅知识库治理

## 使用范围

知识库目前以杭州公开目的地资料和酒店项目运营资料为主。公开目的地资料帮助游客理解地点、适配人群、时长与天气场景；房态、合作资源、服务权益和价格仍以酒店业务数据为准，两者不能互相替代。当前未纳入经审核的政策统计专题库或标杆项目经营拆解，不应把这些类别描述成已具备的数据能力。

## 知识分类与资料要求

| 类别 | 记录内容 | 推荐来源 | 可用于 |
| --- | --- | --- | --- |
| 政策与宏观背景 | 文旅政策、政府公开报告、区域统计口径、发布日期与适用范围 | 政府部门、统计部门、正式政策原文 | 运营分析背景；不得据此推断当前客流或经营结果 |
| 在地资源 | 自然与文化资源、区域、交通提示、季节与客群适配 | 景区/场馆官网、政府文旅平台、现场核验记录 | 游客问答、主题建议、路线候选 |
| 标杆案例 | 项目定位、客群、业态组合、运营模式、公开的收入/投资口径及时间 | 项目方公开材料、政府案例、可追溯研究资料 | 策划参考；注明年份与口径，不把估算当事实 |
| 项目运营资料 | 门票、开放时段、交通、设施、预约、服务权益与合作资源 | 官方运营方页面；酒店库存和商户接口 | 游客回答或产品组合；权益/库存以实时业务源为准 |
| 工作流与质量规则 | 核验、推荐、路线规划、文案生成、异常降级、输出格式 | 本仓库 Skill 与服务端确定性规则 | Agent 执行边界与结果审查 |

政策、统计和标杆案例目前是知识录入规范，不表示仓库已收录相应条目。新增资料前须核对来源、时间和适用范围。

## 事实核验生命周期

1. 新增或被同步改动的事实默认标记为“需核验”，不向游客当作已确认事实呈现。
2. 来源链接检查只记录检查时间和 HTTP 可达性。可访问不代表网页内容正确、及时或适用于本地项目。
3. 运营人员打开原始来源，逐项对照记录字段，并写明核验依据；系统保留操作者、核验字段和时间。
4. 任一策划字段经导入/同步发生变化时，旧核验作废并要求重新核对。定期复核窗口到期后，内容转为待复核。
5. 来源暂时不可访问时保留结果并提示风险；不自动推断开放、预约、门票或资源状态。
6. 任何无来源或超出业务实时数据范围的建议都应明确标注“待确认”，并给出下一步可执行的确认方式。

## 对话工作流

Skill 先判断任务与缺失条件，再读取已提供的知识、业务数据和工具结果；对会改变推荐或安全边界的关键缺失项先询问。无需阻塞的偏好可采用明确假设，并允许用户调整。建议至少给出两种有差异的方案，说明各自适用人群、时间/天气/预算条件、已知限制和信息来源，再给出推荐理由。复杂任务按“确认条件—检索事实—形成候选—校验冲突—解释与确认”分步输出；工具失败时说明缺失事实并提供保守降级方案。

AI 不得捏造来源、政策数据、景区营业信息、交通时长或可预订权益。路线距离/时间若无地图或交通工具结果，应写成待确认，不包装成精确导航。用户未提供的日期、预算、年龄、出行节奏等不应被悄然固定为事实。
