# 业务调研与方案取舍

## 真实痛点

1. 酒店临期房的可售窗口短，单独降价会伤害品牌，也很难解释“为什么值得来”。
2. 周边博物馆、演出、亲子活动和城市体验常有各自的场次、年龄、天气、预约和名额规则；人工拼产品慢，而且容易把不能一起发生的资源放进同一套产品。
3. 运营人员知道最近什么卖得好，但往往需要在聊天、表格、库存系统之间来回切换，难以把经营信号变成可审核的产品草稿。
4. 游客需要的是已确认、可预约的选择，而不是一个绕开酒店审核、能随意占用资源的“行程编辑器”。

## 本方案的选择

酒店是产品供给方和最终审核者。系统把“自然语言生成”收束为酒店 Web/飞书的运营任务：读取近 14 天已确认订单聚合、实时库存、天气和文旅知识，调用 OpenClaw Agent + Skill 生成多个候选；FastAPI 再校验资源 ID、库存、价格、成本、毛利、年龄、天气和时间冲突。候选停在 `PENDING_CONFIRMATION`，只有经营者明确选择“加入草稿”或“确认发布”才改变游客可见状态。

游客端因此只保留已发布产品、预约意向和“问一问”。问一问能解释产品、在当前上架产品中找替代项，但不能生成多日自主组包、锁定任意合作资源或直接发布产品。

## 文旅知识的数据治理

知识库记录景点、博物馆、文化体验、亲子活动和城市漫游点的名称、区域、室内外、适宜人群、年龄、建议时长、开放提示、天气适配、预约说明、来源、来源更新时间和核验状态。它不是库存，也不是可售资源：

- `ACTIVE`：可作为带来源的解释参考；
- `VERIFY_REQUIRED` / `STALE`：Agent 必须说明“信息需确认”，不能把开放时间、预约、票务或场次说成承诺；
- 任一知识项均不能替代酒店的合作资源 ID。

首批杭州知识项覆盖西湖、中国丝绸博物馆、浙江省博物馆孤山馆区、良渚博物院、中国动漫博物馆、浙江自然博物院杭州馆、杭州博物馆、西溪湿地、杭州宋城和杭州植物园，并保留来源链接，方便赛后持续复核。

## 可商业化闭环

酒店通过产品而非裸房销售；合作资源得到稳定的组合流量；游客只看到酒店审核后的可预约产品；订单/预约意向反过来形成聚合经营信号。该结构可扩展到景区、民宿、演艺、文博和亲子乐园，但始终由资源方维护真实库存和规则。
