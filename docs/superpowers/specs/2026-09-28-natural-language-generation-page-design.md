# 自然语言产品生成页精简设计

日期：2026-09-28

## 目标

仅改造商户端的产品生成 / 自然语言生成页面。参数生成页、服务端生成与调整接口、发布流程不在本次重构范围内。

页面默认只展示一个可编辑的主推荐，减少首屏堆叠内容。商户可用一句自然语言生成产品，并持续调整当前主推荐。

## 页面状态

1. 初始状态只显示标题、简短说明、自然语言输入框和生成方案按钮。
2. 生成成功后，输入区保留在顶部；下方只显示一个当前主推荐卡片。
3. 主卡显示名称、客群、时长、建议售价、少量核心卖点，以及查看方案详情、保存为候选两个动作。
4. 候选方案入口位于主卡下方，默认折叠。没有候选时不显示；有候选时显示数量。
5. 主卡下方保留调整当前主方案输入框。每次调整只修改当前主推荐，并展示变化摘要或失败原因。

## 候选方案交互

1. 展开候选后，只显示名称、价格、一行差异摘要和查看详情。
2. 查看详情打开候选详情抽屉或弹窗，不修改当前主推荐。
3. 详情显示完整行程、资源与价格差异。只有设为主推荐可以替换主卡。
4. 设为主推荐后，原主推荐保留在候选列表，避免误操作丢失方案。
5. 保存主推荐沿用既有候选确认与发布逻辑，不自动发布。

## 实现边界

- 页面容器负责会话、生成或调整请求和主推荐状态。
- 主推荐卡、候选折叠区、候选详情弹窗、自然语言输入分别保持单一职责。
- 自然语言输入通过 generate 或 refine 模式复用，避免两套请求逻辑。
- 不改变现有后端 API 请求结构，除非测试证明候选详情无法表达。

## 可用性与异常

- 生成、调整、切换主推荐时禁用对应操作，并显示处理中状态。
- 空输入就地提示；服务端失败时保留原主推荐并说明原因。
- 刷新后恢复当前主推荐和会话，客群与人数必须一致。
- 折叠按钮有 aria-expanded；详情弹窗可关闭并返回原列表位置。

## 验收标准

1. 首次进入不展示候选、操作记录、发布流程或经营依据大区块。
2. 生成后只出现一个主推荐和一个调整输入框。
3. 候选默认折叠，展开不会替换主推荐。
4. 只有候选详情中的设为主推荐操作可以切换主推荐，原主推荐保留为候选。
5. 连续两次自然语言调整都作用于最新主推荐；单人、路线和预算回归用例继续通过。
6. 部署页面完成一次生成、一次调整、一次候选查看和一次主推荐切换的手动验证，且不发布产品。
